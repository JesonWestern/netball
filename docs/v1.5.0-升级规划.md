# NetBall v1.5.0 升级规划

> 主题：CPU 温度改走「系统热区」免提权通道 + 新增 CPU / GPU 功率
> 基线：v1.4.1（`src/app_common.h` `NETBALL_VERSION_STR`）
> 规划日期：2026-11-07
> 前置调查证据：`build/_tmp/probe_power*.txt`、`probe_wmi.cpp`、`probe_nvml.cpp`、`probe_dxgi.cpp`、`probe_setupapi.cpp`

---

## 0. 结论摘要

| 项 | 定案 |
|---|---|
| CPU 温度 | 改用 PDH `\Thermal Zone Information(*)\High Precision Temperature`（0.1 K 分辨率），**不需要管理员**；放弃 ACPI WMI 作为主源 |
| CPU 功率 | PDH `\Energy Meter(*)\Power`，按实例 `rapl_package*_pkg` 求和，单位 mW，**不需要管理员**（Windows 11 EMI） |
| GPU 功率 | NVML `nvmlDeviceGetPowerUsage`，单位 mW，**不需要管理员**；仅 NVIDIA，AMD 独显本期不做 |
| 前置修复 | DXGI 把 3 个虚拟显示驱动（Oray / GameViewer / MuMu）当成显卡，必须先修，否则 GPU 功率出现 3 个空位 |
| 口径声明 | 温度 = **主板/EC 热区**，不是核心结温（Tctl/Tdie）；功率 = **CPU 封装**（APU 上含核显）+ **单卡** GPU，不是整机 |

## 1. 目标与 DoD

**目标**：在保持「免安装、免管理员、单文件 exe」定位不变的前提下，让悬浮球显示 CPU 温度（不再恒为 `--`），并新增 CPU 封装功率与 NVIDIA 显卡功率。

**DoD（完成定义）**：
1. 非提权启动，CPU 温度稳定显示数值，与系统计数器逐点一致（≤1 °C）。
2. CPU 功率、GPU 功率显示 1 位小数瓦特，与独立工具对照 ≤0.2 W / ≤1 W。
3. 任一数据源缺失时显示 `--`，且不影响其它项目、不崩溃、不拖慢主循环。
4. GPU 列表只含真实 PCI 显卡（本机应恰为 2 个）。
5. 稳态资源不劣化：WS ≤ 10 MB、CPU ≤ 0.05%、GDI/USER/Handle 60 s 零增长。
6. 旧配置文件可直接沿用，布局不变。

**非目标（本期明确不做）**：
- 不读核心结温（Tctl/Tdie）——需要内核态
- 不做 AMD 独显功率、不做核显独立功率
- 不做整机功耗、电池功耗
- 不引入任何驱动、不要求提权

## 2. 数据源定案（含实测依据）

### 2.1 CPU 温度

| 项 | 内容 |
|---|---|
| 主源 | PDH `\Thermal Zone Information(*)\High Precision Temperature` |
| 单位 | 分度开尔文（deci-K）。实测 `_tz.thrm = 3352` 与 `Temperature = 335` 同刻一致 → 335.2 K |
| 换算 | `°C = K / 10 - 273.15`（HP 计数器）；`°C = K - 273.15`（普通计数器，作回退） |
| 多热区 | 取全部实例的最大值（多热区机器取最热的那一路） |
| 合法域 | 200.0 K ≤ v ≤ 450.0 K，越界判无效 |
| 采样 | 2000 ms（PDH 原生调用 <0.1 ms，远低于 WMI 的 10–200 ms） |
| 回退链（AUTO） | HWiNFO 共享内存 → **PDH 热区** → ACPI WMI（提权时才有值）→ LibreHardwareMonitor |
| 回退链（仅系统接口） | PDH 热区 → ACPI WMI |
| 失败退避 | 建查询失败 60 s 后重试；读失败不改变查询状态，仅本周期无效 |

**为什么这样排**：HWiNFO 若在运行，给的是真实 Tctl/Tdie，比热区准；热区是免依赖兜底。两者数值含义不同，文档与设置页需注明；需要固定口径的用户选「仅系统接口」。

实测对照：

```
空载  HP=3352 (335.2 K -> 62.0 °C)   普通=335 K
满载  Thermal Zone Temperature = 340 K (66.9 °C)    ← 16 线程 90 s 仅 +4 K
```

> ⚠ 这 +4 K 印证了它是 OEM 定义的热区（板/壳/EC 侧），不是结温。产品文案不得宣称"CPU 核心温度"。

### 2.2 CPU 功率

| 项 | 内容 |
|---|---|
| 源 | PDH `\Energy Meter(*)\Power` |
| 实例匹配 | 名称匹配 `rapl_package<数字>_pkg`（大小写不敏感），多 socket 求和 |
| 单位 | mW（实测 `rapl_package0_pkg` 空载 16093~17407、满载 28642，A/B 对照成立） |
| 陷阱 | `_total` 实例恒为 0，**必须按名字匹配，不能用 total** |
| 合法域 | 0 ≤ v ≤ 2 000 000 mW |
| 采样 | 1000 ms |
| 可用性 | 依赖 Windows 11 的 Energy Meter Interface（EMI/RAPL）；Win10 或无 RAPL 的机器无此计数器 → 显示 `--` |
| 失败退避 | 建查询失败 60 s 后重试 |

### 2.3 GPU 功率

| 项 | 内容 |
|---|---|
| 源 | NVML `nvmlDeviceGetPowerUsage` → mW（实测 19131 mW，enforcedLimit 95000 mW） |
| 触发条件 | 排版含任一 GPU 功率项，或含 GPU 温度项（共用 NVML 初始化） |
| 采样 | 与 GPU 温度同周期 3000 ms |
| 合法域 | 0 ≤ v ≤ 2 000 000 mW；调用返回非 0 判无效 |
| AMD | 不做。`ADL2_Overdrive6_CurrentPower_Get` 返回值语义（百分比 / 瓦）无可靠文档，本机无 A 卡无法实测，不猜 |

### 2.4 前置修复：GPU 枚举

**现状缺陷（实测）**：DXGI 枚举到 5 个非软件适配器——1 张 NVIDIA + 1 张真实 AMD 核显 + 3 个 IDD 虚拟显示驱动（它们借用 AMD 的 vendor/device ID），LUID 各不相同，现有 LUID 去重完全失效：

```
[0] 0x10DE:0x2520  RTX 3060 Laptop
[1] 0x1002:0x1638  luid 0x133A6
[2] 0x1002:0x1638  luid 0x3CDEA
[3] 0x1002:0x1638  luid 0x3CB79
[4] 0x1002:0x1638  luid 0x3C648
Win32_VideoController: 3 个是 ROOT\DISPLAY\000x，只有 2 个在 PCI 总线
```

**修复算法**：
1. SetupAPI 枚举 `GUID_DEVCLASS_DISPLAY`，取 `SPDRP_HARDWAREID` 首项以 `PCI\` 开头的设备，统计 `(VendorId, DeviceId)` 多重集（实测 `total=5 pci=2`）。
2. DXGI 按原逻辑枚举，按 `(VendorId, DeviceId)` 与多重集配对，每对最多保留 `多重集中该组合的数量` 个（按 DXGI 顺序取前 N）。
3. 未配对的（虚拟显示驱动）丢弃。
4. SetupAPI 失败时回退到现有 LUID 去重，避免被清空。

链接需新增 `-lsetupapi -luuid`（已验证 MinGW 13.1.0 可链接、可运行）。

## 4. 技术改动清单

### 4.1 `app_common.h`

```cpp
#define NETBALL_VERSION_STR   L"1.5.0"
#define NETBALL_MAX_ITEMS     18   // 5 基础 + 1 CPU 功率 + 4 卡 × 3 项
// NETBALL_SPEC_CCH 保持 160：18 项全开最长 spec = 138 字符（实测核算）

struct Metrics {
    ...
    int  cpuPwrMw;                 // -1 无效
    BOOL cpuPwrValid;
    int  gpuPwrMw[NETBALL_MAX_GPU];   // -1 无效
    BOOL gpuPwrValid[NETBALL_MAX_GPU];
};
```

> 用毫瓦整数而非 float：跨线程快照不涉及浮点比较误差，渲染时再除以 1000。

### 4.2 `layout_model`

- `ItemId` 追加：`ITEM_CPUPWR`、`ITEM_GPU0PWR`…`ITEM_GPU3PWR`
- `kItems` 追加 token / label：`cpupwr`「CPU 功率」、`gpu0pwr`「GPU0 功率」…
- **签名调整**：`itemGpuIndex(int id, int* idx, bool* isTemp)` → `itemGpuKind(int id, int* idx, int* kind)`，`kind ∈ {GPU_LOAD, GPU_TEMP, GPU_PWR}`；调用点共 4 处（`sensors.cpp` 3 处 + `layout_model.cpp` 2 处）
- `itemText`：功率走独立分支，格式 `CPU 16.5W` / `GPU0 19.1W`（1 位小数，四舍五入到 0.1 W）；无效走 `AddInvalid` → `CPU --`
- `normalize` / `clampConfig`：新 token 自动纳入，无需特殊处理

### 4.3 `sensors.cpp`（改动最大）

1. **PDH 分层重构**：现有 `InitPdh()` 把「加载 dll」「建 GPU Engine 查询」耦合在一起，且任一失败就 `ReleasePdhDll()`。改为：
   - `EnsurePdhDll()`：只负责加载与取函数指针
   - `EnsureGpuLoadQuery()` / `EnsureTzQuery()` / `EnsureEnergyQuery()`：三条独立查询，各自失败互不影响
2. 新增 `CollectThermalZoneTemp(int* outDeciK)`：读 HP 计数器，失败回退普通计数器
3. 新增 `CollectCpuPowerMw(int* outMw)`：`Energy Meter` + `rapl_package*_pkg` 求和
4. NVML：新增 `pNvmlPower`，`ReadNvmlPowerMillis()`
5. `InitNvml()` 触发条件由 `wantGpuTemp` 扩为 `wantGpuTemp || wantGpuPwr`
6. `EnumerateGpus()`：接入 SetupAPI 的 PCI 多重集过滤
7. 新增门控 `g_wantCpuPwr` / `g_wantGpuPwr`（由 `setConfig` 按 spec 计算）
8. 排程：`nextTz`（2 s）、`nextCpuPwr`（1 s）、`nextGpuTemp`（3 s，与 GPU 功率共用）

### 4.4 配置与兼容

- 不新增 ini 键（功率项走 spec token，与现有 13 项同构）
- 旧 spec → 新版本：未知 token 不受影响，正常解析
- 新 spec → 旧版本：旧版本 `itemFromToken` 返回 -1，token 被丢弃，**优雅降级**（不崩、布局少几项）

## 6. 验收标准（AC）

| 编号 | 判据 | 方法 |
|---|---|---|
| AC-21a | 非提权启动，CPU 温度非 `--`，且与 `Get-Counter '\Thermal Zone Information(*)\High Precision Temperature'` 同刻换算值差 ≤ 1 °C | 10 次同步采样 |
| AC-21b | CPU 功率与 `\Energy Meter(rapl_package0_pkg)\Power`/1000 差 ≤ 0.2 W | 10 次同步采样 |
| AC-21c | GPU 功率与 `nvidia-smi --query-gpu=power.draw` 差 ≤ 1 W | 5 次同步采样 |
| AC-21d | 满载 A/B：功率较空载上升 ≥ 5 W（本机基线 16.1 → 28.6 W） | `busy.exe` 16 线程 60 s |
| AC-22a | `NETBALL_DISABLE_EMI=1` 时 CPU 功率显示 `--`，其余项目正常 | 环境变量注入 |
| AC-22b | `NETBALL_DISABLE_TZ=1` 时 CPU 温度回落 HWiNFO/WMI/`--`，不崩 | 环境变量注入 |
| AC-23 | 本机 GPU 数 = 2，名称 = `NVIDIA GeForce RTX 3060 Laptop GPU` + `AMD Radeon(TM) Graphics`，不含 Oray / GameViewer / MuMu | 设置窗 + 日志 |
| AC-24a | 用现有 `config.ini`（13 项 spec）启动，布局不变，退出后 ini 未被改坏 | sha256 前后对比 |
| AC-24b | 18 项全开 spec 往返一致（format → parse → format 相同） | 单元探针 |
| AC-25 | 60 s 稳态：WS ≤ 10 MB、CPU ≤ 0.05%、GDI/USER/Handle 零增长 | PowerShell 采样 |
| AC-26 | 退出后无残留进程、无 `_unins.tmp` 类僵尸 | tasklist |
| AC-27 | `-Wall -Wextra` 零告警；exe ≤ 2 MB | build.bat 输出 |

> `NETBALL_DISABLE_EMI` / `NETBALL_DISABLE_TZ` 是**测试钩子**，仅用于验证降级路径，正常路径不读取；需在发布说明中注明。

## 7. 风险与对策

| # | 风险 | 影响 | 对策 |
|---|---|---|---|
| R1 | 热区值是板温，用户误当核温 | 观感/信任 | 文案不写"核心"；文档明示；设置页注明"系统接口 = 主板/EC 热区" |
| R2 | APU 上 `pkg` 含核显 | 数值偏大 | 文案写"CPU 封装功率"；文档说明组成 |
| R3 | Win10 / 无 RAPL 机器没有 Energy Meter | 功率恒 `--` | 已设计降级；AC-22a 覆盖 |
| R4 | `rapl_package0_pkg` 实例名非微软承诺值 | 换平台失配 | 用「前缀 `rapl_` + 后缀 `_pkg`」匹配，不硬编码数字；首帧把实际实例名写 `OutputDebugString` |
| R5 | 多热区机器取最大值可能不是 CPU 侧 | 数值偏差 | 文档说明；必要时后续加"按实例名优选" |
| R6 | SetupAPI 失败导致 GPU 列表为空 | 功能丢失 | 回退到 LUID 去重（保底不空） |
| R7 | `NETBALL_MAX_ITEMS` 13→18 影响 `text_render` 栈上数组 | 栈占用增加 | 实测单结构增量 < 1 KB，无风险；编译期断言兜底 |
| R8 | 引号/编码坑：PS 脚本含中文被按 ANSI 解码 | 脚本崩 | 沿用既有约定：`.ps1` 全 ASCII，中文用码点构造 |
| R9 | 打包脚本的 payload 尺寸/sha 硬校验 | 打包失败 | M4-2 同步更新期望值 |

## 8. 被排除的方案

| 方案 | 为什么排除 |
|---|---|
| 自带内核驱动读 MSR / SMN（AIDA64 的路子） | 需要 EV 签名；WinRing0 系驱动已被微软列入易受攻击驱动名单，HVCI/内存完整性开启时拒绝加载，杀软拦截；为悬浮球引入驱动不划算 |
| 让用户以管理员运行 NetBall | 破坏「绿色免安装」定位；且提权后 ACPI WMI 给的仍是热区，精度收益极小 |
| 读 AIDA64 共享内存 | 需 AIDA64 常驻并手动开启共享内存，依赖过重；可作为 v1.6 的增量源（图吧工具箱里有 AIDA64，但不应成为硬依赖） |
| AMD 独显功率（ADL `Overdrive6_CurrentPower_Get`） | 返回值语义（百分比 vs 瓦）无可靠文档，本机无 A 卡无法实测，宁可 `--` 不猜 |
| 由 CPU 占用率估算功率 | 属于伪造数据，违反真实性要求 |
| 直接把 `\Power Meter(*)\Power` 当整机功耗 | 本机实测恒为 0，不可用 |

## 11. 执行方式

- **实现**：单线顺序推进（改动集中、互相耦合，拆并行反而撞文件）
- **验证**：独立验收（不与实现同一上下文），按第 6 节 12 条逐条实测并留证据至 `docs/verify/v6/`
- **留痕**：每个里程碑结束更新 `.agent/board.md`，证据落 `build/_tmp/v6/`
- **清理**：`build/out` 只留 `NetBall.exe`；探针脚本归入 `build/_tmp/`
