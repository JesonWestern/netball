## 4. 已知限制（必读）

### 4.1 设置窗在极端分辨率下的可用性
设置窗客户区在 **175% DPI 下为 844 物理像素高**（384×456 DIP → 672×798 物理）。1080p（1920×1080）在 175% 缩放时可完整显示；**更低分辨率或更高缩放时**依赖工作区钳制保证标题栏与底部按钮可见，**内容不滚动**——即可能出现中部控件被裁切而按钮仍在的情况。裁决记录：`.agent\workflow.md` DECISIONS #18。

### 4.2 AC-8 的物理不可行区（数学边界，非缺陷）
文字色与背景色的合成模型：

```
叠纯黑桌面：Cb = a·C
叠纯白桌面：Cw = a·C + (1−a)·255
maximin 判据：M = max( min(cr(黑, Cb), cr(黑, Cw)),  min(白, ... ) )
M < 4.5 即该 (颜色, 不透明度) 组合物理上不可行
```

实测不可行区边界：

| 不透明度 | 不可行灰度区间 | 最差 M |
|---|---|---|
| 100% | 无不可行区 | — |
| 85% | 灰度 95 ~ 135 | 3.54 |
| 70% | 灰度 6 ~ 165 | — |
| 60% | 灰度 30 ~ 190 | — |
| ≤40% | **全灰阶不可行** | — |

含义：用户在 85% 不透明度下若自定义选中灰（约 RGB 95~135），无论选黑字还是白字都无法达到 4.5:1。**8 个预设色已全部规避该区**（AC-8 全 PASS），落入该区的只有用户自定义色。处置口径见 `.agent\workflow.md` DECISIONS #29（判 `KNOWN-LIMITATION`，须列明组合与建议「提高不透明度至 ≥85%」，**不等同于 PASS**）。

### 4.3 提权安装路径未实跑
`NetBall.iss` 第 81–82 行为 `PrivilegesRequired=admin` + `PrivilegesRequiredOverridesAllowed=commandline`：普通双击默认安装到 `{autopf}\NetBall`（即 `%ProgramFiles%\NetBall`）并请求 UAC。**本验证环境无法应答 UAC 弹窗，该路径完全未实测**，相关结论不可外推。

已完整验证的是 `/CURRENTUSER` 分支：安装目录 `%LOCALAPPDATA%\Programs\NetBall`，卸载键 `InstallLocation` 同值（`docs\audit\AUDIT-REPORT-R3.md` §3：`/CURRENTUSER` 安装、卸载键 `DisplayIcon={app}\NetBall.exe` 实测存在）。
静态复核可确认：全脚本**无任何 HKLM 写入**，Uninstall 信息由 Inno 按安装模式一致地写 HKLM 或 HKCU（`.agent\board.md` T8 行「提权模式静态复核」）。

### 4.4 per-user 边界
- （a）`HKCU\...\Run\NetBall` 的 `uninsdeletevalue` **只清「执行卸载者」自己账户**的值。多用户各自开过自启时，其它账户的 Run 值会残留，指向已被删除的 exe。
- （b）`{userappdata}` 在卸载时解析为**执行卸载者**的 `%APPDATA%`。A 装 B 卸时，「是否保留配置」的询问针对 B 的配置目录。
- 依据：`installer\NetBall.iss` `[Registry]` 注释中的提权模式静态复核（唯一 HKCU 动作只在卸载时作用于「执行卸载者」账户）+ `docs\verify\v2\` 目录下的 T9 报告 §F.3（上一版包的同构实测）。

### 4.5 无代码签名
安装包与主程序均未做 Authenticode 签名，首次运行/安装会触发 SmartScreen「未知发布者」提示。`assets\installer\README.txt` 已对用户说明。**不伪造签名**（`.agent\workflow.md` DECISIONS #5）。

### 4.6 网速读数的语义
球面显示的是**整机网卡吞吐**（口径：`OperStatus==Up ∧ IfType∉{24,131} ∧ InterfaceAndOperStatusFlags.FilterInterface==0`），不是单条连接的速率。因此与浏览器/下载工具显示的数值**不可直接比较**：后台若有其它流量，球会高于单个下载工具的数倍。同时，Windows 的 WFP/QoS 过滤层会为同一块物理网卡复制 4~5 行同值计数器，已按 `FilterInterface` 剔除；若不去重会放大约 4 倍（实测 all-up `in=546,264` vs hardware-only `in=136,529`，见 `src\metrics.cpp` 文件头注释与 `build\_tmp\d1-evidence\_ifdump.log`）。

### 4.7 payload 解包为授权回退口径
`docs\verify\v2\` 目录下 T9 报告 §A 的内嵌 payload 校验采用**回退口径**（本版的三点闭环实测见 `docs\audit\AUDIT-REPORT-R3.md` §3）：本机无 7-Zip，innoextract 1.9 对本包（Inno 6.7.3）报 `Unexpected setup loader revision: 2`，故第 1 段以「装到临时目录后取 Inno 解压出的落盘文件」代替直接解包。该口径以三点哈希闭环（包内 → 落盘 → `build\out` 源文件）支撑，**残余风险**：不覆盖「压缩流损坏却恰好解压成功」这类极端情形。

### 4.8 自动文字色的判定依据（v1.4.3 起按真实画面采样）
`render::resolveAutoTextColor` 在画字之前**采样已合成好的表面像素**（材质、模糊、浓度、壁纸/任务栏底色全部计入），半透明表面再叠加 `glass::backdropColor` 给出的背景均色，还原「屏幕上实际看到的那块颜色」，再按 WCAG 取黑/白中对比度更高者；无底板时直接按表面背后的背景明暗判定。因此同一颗浅色玻璃球放在深色壁纸上显示白字、放在浅色壁纸上显示黑字，任务栏面板同理。
只有采样与背景都取不到（系统亚克力实时模糊、抓屏失败）才回退旧的 `render::autoTextColor` maximin 推导（maximin <4.5 时按典型中灰桌面退化，见 4.2 节）。回退路径的退化行为写在 `src\render.cpp` 头注释中，裁决记录见 `.agent\workflow.md` DECISIONS #39。
仍未消除的边界：表面与文字恰好同为中灰（约 `#75`~`#95`）时，黑白两色的对比度都接近 4.5:1，此时由绘制层的反色柔光保证边缘可读；4.2 节的物理不可行区对「无采样回退路径」仍然成立。

### 4.9 默认背景色不属于 8 个预设色（对应审计 D-09）
默认背景色为 `#181C24`（`src\config.cpp` 出厂默认值），而设置窗的 8 个预设色里最接近的深灰是 `#262A34`（`src\settings_dialog.cpp` 的 `kPresets[8]`），两者不相等。后果：**首次打开设置窗时，没有任何一个色块显示为选中状态**，界面看起来像「没选中任何预设」。这是既定产品行为（默认色为程序自选、预设色块只标记「用户点过的预设」），**不是缺陷，本轮不改代码**。用户点击任一色块即可套用对应预设色。

### 4.10 跨 DPI 触发「重置位置」的越界（对应审计 D-10）

**已知缺陷**｜跨 DPI 触发「重置位置」时，球右缘可能越界 ≤20px（约 87% 可见，仍可拖动/可再次重置）｜计划 **v1.1** 于 `WM_DPICHANGED` 内 `SetWindowPos` 后调用 `ClampWindowFullyInside` 修复。

复现路径：球停在**低 DPI 副屏**（本机左屏 120 dpi）时执行「重置位置」——默认位置按**旧 DPI 下的 110 px 边距**算出；随后窗口被拖到 175%（168 dpi）主屏，`WM_DPICHANGED` 触发、尺寸按新 DPI 放大到 154 px，同一 110 px 边距在新 DPI 下不足以把窗口完全留在屏内，实测**右缘越出虚拟屏 20 px**：球约 **87% 可见，仍可点击、可正常拖动**。

根因（已定位到代码）：`WM_DPICHANGED` 分支里尺寸变了，但**没有做二次钳制**，用旧 DPI 换算出的坐标没有被新屏幕边界重新约束——即坐标换算少了一步，属实现遗漏。

影响与规避：球仍可点击、可拖动；再点一次「重置位置」或在当前屏拖动即可回到屏内。功能不受损、数据不受影响。

修复计划（v1.1，见 §6 第 7 条）：`WM_DPICHANGED` 内 `SetWindowPos` 之后调用 `ClampWindowFullyInside`，并补一条自测——低 DPI 屏把 size 由 48 调到 160，再拖到高 DPI 屏，断言窗口完全位于虚拟屏内。

## 5. 验证方法与可信度

### 5.1 锚点三元组与测量纪律
每次测量必须绑定唯一二进制：**path + bytes + sha256**（mtime 仅作辅助，因为重建会改 mtime 但不改内容）。测量前后各算一次 sha，不一致即判 `BLOCKED-被替换`，本轮数据全部作废。

本项目一天内出现过 6 个构建，**前 5 个（18:36 / 19:02 / 19:05 / 21:28 之前的各版）的全部测量数据已作废**，只有最终交付的 `e085727cf87e4df22b551596b2cb53d407ef177ba2539b4d9e6ac0fb33ebe983` 的结果进入验收。锚点历史与作废原因见 `docs\verify\v4\V4-REPORT.md` §0 与 `.agent\workflow.md`。

### 5.2 `BLOCKED-*` 十道门禁
验证脚本在**启动任何被测程序之前**逐项检查，任一不满足即中止并上报，不产出结论：

| 门禁 | 触发条件 |
|---|---|
| `BLOCKED-SETUP` | 前置环境不满足（缺工具/缺文件） |
| `BLOCKED-BUSY` | 已有 NetBall 实例占用全局互斥体 `NetBallSingleInstance` |
| `BLOCKED-NOWND` | 目标窗口不存在 |
| `BLOCKED-NODLG` | 期望的对话框未出现 |
| `BLOCKED-DPI` | DPI 上下文错误（size=88 未得 154×154） |
| `BLOCKED-STALE` | exe 早于源码 |
| `BLOCKED-ANCHOR` | sha ≠ Leader 广播值 |
| `BLOCKED-REPLACED` | 测量前后 sha 不一致 |
| `BLOCKED-SHOT` | 截图无效（`ink=0` 或纯色） |
| `BLOCKED-NOWINDOW` | 未获本轮窗口许可 |

门禁的有效性有实证：2026-11-02 晚 Leader 广播的锚点串因人工转写丢了一个 `0`、挪了一个 `A`，verifier-3 的 `BLOCKED-ANCHOR` 在 `Start-Process` **之前**中止并上报，未自行裁定「内容等价」，避免了全员测量作废（`.agent\workflow.md` DECISIONS #74）。

### 5.3 三类「假成功」陷阱与本项目的应对
这三类问题**都不报错**，只表现为「数据与另一条证据打架」，只能靠交叉核对发现：

| 陷阱 | 表现 | 本项目应对 |
|---|---|---|
| ① 探针位置错误 | AC-6 的中心探针落在文字带上，把字形像素当成形状像素 → 胶囊被误判 FAIL | 用形状覆盖率 + 10% 弦内缩 + 四角判据替代单点探针；修正后重算同一批截图（`docs\verify\media-t7b\ac6-reanalyze.log`） |
| ② 空值被当成零 | `Get-FailCount` 零失败时返回 `$null`，`$null -lt 1` 为真 → 全 PASS 被写成 `RESULT: FAIL` | 断言改 `@(...).Count`；已作废的 `RESULT: FAIL` 保留在案并在 HANDOVER-V4 附表标注不得引用 |
| ③ 缺形状掩膜 | `-ExpectText` 不做掩膜，亮壁纸下桌面像素被当字形 → 误判文字溢出 | 几何掩膜 + 众数；与 builder 侧独立实现逐张比对，差 ≤0.06 |

补充两类工程型「假成功」（已在规程层面禁掉）：
- **假 rc=0**：`cmd /c "... & echo rc=%errorlevel%"` 中 `%errorlevel%` 在整行解析期展开，永远滞后一拍。→ 一律用 `cmd /v:on` + `!errorlevel!` 或 PowerShell `$LASTEXITCODE`；**更根本的一条：用产物判成功而非返回码**（构建看 `[4/4] artifacts` + exe 元数据，脚本看 `RESULT:` 行，截图看 `ink>0` 且非纯色）。
- **DPI 虚拟化**：DPI-unaware 宿主里 `GetWindowRect` 返回被缩放前的逻辑坐标（175% 下差 1.75 倍），足以把 154 px 的球读成 88 px、把正常渲染误判成「无文字」。→ 取 rect/截图前必须 `SetThreadDpiAwarenessContext(-4)`，并以 `size=88 → 154×154` 自检门禁兜底。

### 5.4 结论可信度分级（阅读本文件时请按此取舍）
- **A 级（可外推）**：AC-1/2/5/9/11/16 与 AC-13/14/15 —— 只读文件系统 + 注册表 + 独立哈希 + 静默安装/卸载，不依赖视觉判读。
- **B 级（依赖机读但链路已自检）**：AC-3/4 —— 屏幕 OCR + 独立 `GetIfTable2`/`GlobalMemoryStatusEx` 对照；OCR 参数经调优（`Scale 6 / Threshold 0 / Crop 0.24`，mem 3/3、down 3/3）。
- **C 级（依赖像素判读，已做几何掩膜与多帧复核）**：AC-6/7/8/17 —— 每项均有数学层与图像层双重判据，且图像层与 builder 侧独立实现交叉比对。
- **未覆盖**：提权安装路径（4.3）、payload 直接解包（4.7）、跨账户卸载（4.4）。

## 6. 后续建议（v1.1）

1. **文字区局部 100% 不透明底板**：可根治 4.2 节的物理不可行区——把文字背后的区域抬到 alpha=100%，则任意灰度背景 × 黑白文字都能达到 4.5:1。v1.0 否决该方案的理由是它改变视觉观感（球心出现不透明底板）且触碰渲染主链路，属「v1.1 确定性修复方案」（`.agent\workflow.md` DECISIONS #37）。
2. **`build.bat` 构建前自动归档**：在构建前把现有 `build\out\NetBall.exe` 复制为 `build\_tmp\archive\NetBall_<sha8>.exe`，避免「重建覆盖即丢失旧产物」。本项目已手工补建归档目录（四代产物在 `build\_tmp\archive\`），建议固化为脚本第一步。
3. **`NETBALL_DEBUG_METRICS` 调试输出**：v1.0 依赖屏幕 OCR 做 AC-3/AC-4 机读，链路长且受 DPI/壁纸干扰。若后续需要更强可测性，可增加受环境变量开关的调试通道（写 `%TEMP%\NetBall_metrics.txt` 或 `--dump-metrics`），使验证不再依赖像素识别。
4. **`--no-insert-timestamp` 已落地**：`build.bat` 链接行已含 `-Wl,--no-insert-timestamp`，PE 头 `TimeDateStamp=0`，**同源码重建得到相同 sha256**（实测 19:10:07 与 19:10:18 两次构建 sha 完全相同），从机制上消除「重建即变锚点」类事故。后续改动该文件后必须保持该参数，并跑 `python -c "print(open(r'build\build.bat','rb').read().isascii())"` 断言 `True`（文件须保持纯 ASCII，中文注释在 GBK 控制台下会吃掉行尾 CR 并把注释尾巴当命令执行）。
5. **提权安装路径补齐**：在可应答 UAC 的干净虚拟机上补跑 `%ProgramFiles%` 安装/卸载一轮，补上 4.3 的空白；同时验证多账户下的 4.4（a）（b）两条边界。
6. **AC-8 不可行区的用户侧提示**：当用户自定义色落入 `M<4.5` 区域时，设置窗可给出即时提示并建议「提高不透明度至 ≥85% 或改用预设色」，把 4.2 的数学限制前移到交互层，而不是只写在文档里。
7. **跨 DPI 重置位置的二次钳制**（对应 4.10 / 审计 D-10）：在 `WM_DPICHANGED` 处理中，`SetWindowPos` 之后补一次 `ClampWindowFullyInside`，消除"重置后残留 ≤20 px 悬边"。同步补一条自测：低 DPI 屏把 size 由 48 调到 160，再拖到高 DPI 屏，断言窗口完全位于虚拟屏内（当前仅 87% 可见）。
8. **`IsPositionUsable` 改名为 `IsPositionUsableForRestore`**：该函数只在「恢复 ini 里的位置」这一处语义下成立，现在的名字容易被后续代码误用到「拖动落地」等其它路径。**用名字挡住误用，比补测试便宜**（一处重命名 + 调用点同步，无行为变化）。
