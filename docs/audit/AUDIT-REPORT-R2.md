## 7. 本轮新增/遗留风险

1. **跨 DPI 是修复后的新薄弱面**。D-06 把「拖动」做得很严（每一帧钳制），但**尺寸变化**这条链路（`WM_DPICHANGED`）没有接钳制；D-10 就是它在「重置位置」上的表现。同类隐患：在低 DPI 屏把 size 从 48 调到 160 再拖到高 DPI 屏，可能瞬间越界（本轮未单独构造）。
2. **「验收口径」与实际实现存在两套阈值，且只靠注释约束**。`ClampFullyInsideVirtualScreen` 与 `IsPositionUsable` 的调用面目前清晰，但没有任何断言/测试防止后来者把 `IsPositionUsable` 塞进 `WM_LBUTTONUP`——一旦塞进去，D-06 会以「看不见的方式」复发。
3. **verifier-5 报的 D-01/D-06 结论我复现为成立，但两处证据比我的更宽松**：其 AC-7 记 0.977（我 1.000）、其「20px 悬边」只给了结论未给原始 rect。差异不影响判定，但说明「同一现象、不同工具、不同位数」仍是本项目的老问题。
